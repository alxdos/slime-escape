# Content Archetypes from Markdown

- Status: in-progress
- Created: 2026-04-23
- Updated: 2026-04-23

## Game designer

- Sees: три новых MD-файла в `content/` — `content/weapons.md`, `content/drops.md`, `content/bosses.md` — каждый по тому же формату, что и `content/enemies.md` из истории 011 (партиция определений + партиция `# Balance` с узкими сравнительными таблицами). Дополнительно: в `content/enemies.md` секции `## Sounds` и `## Voice` дозаполнены так, что `hit`, `death` и `voice` ссылаются на **разные** пулы сэмплов слаймов.
- Can do: открыть нужный MD, поправить параметр (например, `pistol.cooldownMs`, `heal-orb.effect.amount`, `slime-king.maxHp` или `slime-fast.voice.sampleIds`), запустить `npm run content:build` и `npm run dev`, сразу увидеть/услышать изменение в игре. Опечатки и ссылки на несуществующие `id` ловятся генератором с понятным сообщением и не портят рабочий конфиг.

## Technical

- Конвейер генерации, формат MD и правила пар `<area>.ts ↔ <area>.generated.ts` остаются прежними — фиксированы в [../design/content-authoring.md](../design/content-authoring.md). Эта история переиспользует существующий генератор `scripts/content-build/`, добавляя три новые области рядом с уже работающей `enemies`.
- Распределение по слоям:
  - **weapons** → `src/shared/content/weapons.generated.ts` (потребитель — `weapons.ts` с типом `WeaponArchetype` и реестром `WEAPON_ARCHETYPES`) и `src/main/audio/weaponAudio.generated.ts` (потребитель — `AudioMappings.ts`, owner типа `WEAPON_AUDIO_MAPPINGS`);
  - **drops** → `src/shared/content/drops.generated.ts` (потребитель — `drops.ts` с типом `DropArchetype`/`DropEffect` и реестром `DROP_ARCHETYPES`); audio-парности нет — `EVENT_AUDIO_MAPPINGS.dropPickup` остаётся inline в `AudioMappings.ts` и в эту историю не входит;
  - **bosses** → `src/shared/content/bosses.generated.ts` (потребитель — `bosses.ts` с типом `BossArchetype` и реестром `BOSS_ARCHETYPES`) и `src/main/audio/bossAudio.generated.ts` (потребитель — `AudioMappings.ts`, owner типа `BOSS_AUDIO_MAPPINGS`).
- Формы `WeaponArchetype`, `DropArchetype`, `DropEffect`, `BossArchetype`, `BossPhaseSpec`, `BossAttackSpec` ([../design/content-archetypes.md](../design/content-archetypes.md)) и `EnemyAudioMapping`, `BossAudioMapping`, аудио-маппинг оружия ([../design/audio.md](../design/audio.md)) — **не меняются**. Генератор укладывается в существующий контракт; любое поле, которое не выражается через эти формы, — сигнал к новому решению, а не к расширению по месту.
- `content-authoring.md` пополняется правилом «дозаполнение, а не урезание»: при расхождении между парой `content library` ↔ presentation (или внутри одной области между несколькими слоями) источник правды — **более полное** состояние; недостающее дозаполняется в MD, а не вычищается до минимума. Это правило применяется как к `weapons` (в `WEAPON_AUDIO_MAPPINGS` и в `SampleRegistry` уже зашиты `pistol`/`shotgun`/`smg`/`sniper`/`laser` — в MD заводятся все пять архетипов, не только `pistol`), так и к `enemies` (в `SampleRegistry` уже три отдельных пула `slimes/hit-*`, `slimes/death-*`, `slimes/voice-*` — `enemies.md` дозаполняется так, чтобы эти пулы реально использовались).
- Структурные инварианты 011 переиспользуются без расширения формата:
  - reference-чек «`id` в любой балансной/sound-таблице существует как H2 в партиции определений» — теперь применим и для weapons/drops/bosses;
  - вложенные коллекции (`phases[]`, `attacks{}` у босса; `dropTable[]` у врагов) выражаются плоскими таблицами с `id` цели и несколькими строками на одну сущность — ровно как `## Drops` у enemies в 011;
  - `BossPhaseSpec.allowedAttackIds` записываются как list-in-cell через запятую;
  - cross-reference внутри области (`phase.allowedAttackIds ⊆ ## Attacks` того же `bossId`; `dropArchetypeId ∈ DROP_ARCHETYPES`) проверяется парсером области.
- Рантайм-валидаторы (`validateEnemyRegistry`, `warnIfWeaponMayTunnel`, `validateMappings` в `createAudioMappings`, проверки drop-таблиц) продолжают работать поверх сгенерированных данных — генератор их не дублирует и не подменяет.

## Out of scope

- Сессии и encounter-композиция (волны, передышки, preset-каталог `playableModes`, `buildSession.ts` с описанием spawn-планов и encounter-ов) — отдельная история, требует собственного design-решения о формате описания волн и encounter-переходов.
- Players (`SANDBOX_PLAYER`/`TRAINING_PLAYER`) и Arenas (`SANDBOX_ARENA`) — связаны с session-композицией, едут вместе с ней.
- Presentation-области без пары в `content library` (`SampleRegistry`, `EVENT_AUDIO_MAPPINGS`, `WEAPON_AUDIO_MAPPINGS`-style fields, не привязанные к архетипам) — отдельная история; требует точечного расширения `content-authoring.md` про MD-источники для чисто presentation-слоя.
- Расширение `DropEffect` новыми `kind`-ами (например, `weapon-swap`, `speed-up`) и расширение реестров за пределами уже намеченных сущностей (новые боссы, новые типы дропа). История переводит существующие литералы в MD; новые типы — задача того, кто их вводит как gameplay-фичу.
- Per-drop и per-boss-hit/death audio-каналы — нет ни sample-зерна в `SampleRegistry`, ни маппинга в `AudioMappings.ts`; вводятся, когда появляются файлы.
- Горячая перезагрузка MD без перезапуска `npm run dev`, UI-редактор поверх MD, любые форматы кроме Markdown — те же out-of-scope, что и в 011.

## Acceptance

- В репозитории есть три новых MD-файла: `content/weapons.md`, `content/drops.md`, `content/bosses.md`. Каждый — единственная точка правды для своей области, со структурой по правилам [../design/content-authoring.md](../design/content-authoring.md):
  - партиция определений (`# Weapons` / `# Drops` / `# Bosses`), внутри H2 на каждую сущность с таблицей `field | value` для именной части (`displayName`, `color`);
  - партиция `# Balance` с узкими (≤5 колонок) сравнительными таблицами по группам параметров: для weapons — `## Cooldown`, `## Projectile`, `## Damage`, `## Sound`; для drops — `## Body` (radius/ttlMs), `## Effect` (kind/amount); для bosses — `## Body`, `## Movement`, `## Contact damage`, `## Knockback`, `## Phases` (несколько строк на `bossId`), `## Attacks` (несколько строк на `bossId`), `## Sounds`.
- `npm run content:build` перегенерирует все целевые файлы:
  - `src/shared/content/{weapons,drops,bosses}.generated.ts` — литералы под существующие типы из соответствующих рукописных модулей;
  - `src/main/audio/{weaponAudio,bossAudio}.generated.ts` — `WEAPON_AUDIO_MAPPINGS` и `BOSS_AUDIO_MAPPINGS` под существующие типы из `AudioMappings.ts`.
  - Потребители (`weapons.ts`, `drops.ts`, `bosses.ts`, `AudioMappings.ts`) импортируют сгенерированные литералы. Реестры, типы и валидаторы остаются в рукописных файлах.
- После сходимости `WEAPON_ARCHETYPES` содержит **пять** оружий: `pistol`, `shotgun`, `smg`, `sniper`, `laser`. У каждого — различимая игровая роль, выраженная значениями полей `cooldownMs`/`projectileSpeed`/`projectileRadius`/`projectileTtlMs`/`damage` (а не вариация pistol-а): `pistol` — baseline; `shotgun` — высокий разовый урон, длинный cooldown, низкая скорость и короткий ttl; `smg` — короткий cooldown, низкий урон; `sniper` — самый длинный cooldown, самый высокий урон и скорость снаряда; `laser` — короткий cooldown, очень высокая скорость снаряда, низкий урон, тонкий радиус. Конкретные числа выбирает геймдизайнер при авторинге MD.
- `WEAPON_AUDIO_MAPPINGS` после генерации содержит ровно те же пять записей, что и до истории (`fire` sampleId на каждый из пяти архетипов); инвариант «`id` из аудио-таблицы ⊆ `id` из партиции определений» соблюдается; `validateMappings(SampleRegistry)` проходит без warning-ов о неизвестных sampleId.
- `DROP_ARCHETYPES` после генерации содержит `heal-orb` байт-в-байт с текущим литералом; `BOSS_ARCHETYPES` после генерации содержит `slime-king` (со всеми двумя фазами и тремя атаками) байт-в-байт с текущим литералом; `BOSS_AUDIO_MAPPINGS` без изменений.
- `content/enemies.md` дозаполнен:
  - в `## Sounds` колонка `death` для `slime-fast`/`slime-tank` использует пул `slimes/death-1, slimes/death-2, slimes/death-3, slimes/death-4` (а не `slimes/hit-*`);
  - в `## Voice` колонка `sampleIds` для `slime-fast`/`slime-tank` использует пул `slimes/voice-1, slimes/voice-2, slimes/voice-3, slimes/voice-4`.
  - После генерации `src/main/audio/enemyAudio.generated.ts` константа `SLIME_VARIANTS` исчезает: `hit`, `death` и `voice` каждого слайма ссылаются на свои пулы; `voice` звучит на `defaultGain: 0.3` из `SampleRegistry` (как требует [../design/audio.md](../design/audio.md)).
- Поведение игры по weapons/drops/bosses не меняется относительно текущего: фактически в активных preset-ах используются только `pistol`/`heal-orb`/`slime-king`, и для них значения остаются прежними. Поведение слаймов меняется в звуке: смерть и voice звучат своими файлами/громкостью — это и есть приведение к design-намерению `audio.md`.
- При любой ошибке в любом MD генератор падает с понятным сообщением (файл, секция, строка, поле, что ожидалось) и **не пишет ничего** в выходные файлы — атомарность из 011 распространяется на все четыре области сразу. Cross-reference-ошибки (`phase.allowedAttackIds` с несуществующим `attackKey`, `dropArchetypeId` без записи в `## Drops` партиции, `id` в balance/sound без H2 в defs) ловятся парсером соответствующей области.
- CI ловит дрейф для всех областей: `content:check` уже встаёт первым в `build` (история 011), новые целевые файлы попадают в проверку автоматически.
- `npm test` остаётся зелёным.
- Demo (weapons): геймдизайнер открывает `content/weapons.md`, меняет `pistol.cooldownMs` с `250` на `120`, запускает `npm run content:build` и `npm run dev`, видит заметно более частую стрельбу в режимах `Тренировка` и `Побег`.
- Demo (drops): меняет `heal-orb.effect.amount` с `1` на `3`, пересобирает, подбирает дроп и видит, что HP восстанавливается на 3 единицы.
- Demo (bosses): меняет `slime-king.maxHp` с `40` на `20`, пересобирает, проходит финал `Побега` за заметно меньшее число попаданий.
- Demo (enemy sound): после дозаполнения `## Voice` по `slimes/voice-*` геймдизайнер запускает `Тренировку`, на ambient-голосах слаймов слышит заметно более тихий звук, чем при попадании по тому же слайму (фактическое приведение к `audio.md`: voice-сэмплы звучат на `defaultGain: 0.3`, hit — на `1.0`).
